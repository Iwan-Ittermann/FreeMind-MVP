==================================================
9) ROOT CAUSE IDENTIFIED (ROUND 3)
==================================================
The issue was a **channel instance collision**:
- `useChatMessages` created a NEW ephemeral channel with the same name
  `topic-{topicId}-animations` as the persistent listener in `useTopicData`.
- Supabase JS client's `supabase.channel('name')` creates a NEW channel
  instance each time — two instances with the same name do NOT share state.
- The `self: true` flag only means "the channel instance that sent the
  message also receives it back" — since sender and receiver were different
  instances, this didn't help.
- The ephemeral channel was subscribed, sent the broadcast, then immediately
  removed — but the PERSISTENT listener channel never received the event
  because Supabase Realtime treats them as separate subscriptions.

==================================================
10) FIX APPLIED (ROUND 3) — RESOLVED
==================================================
Created a shared animation channel registry:

File: src/lib/animation-channel.ts (NEW)
- Central Map<string, RealtimeChannel> registry.
- Exports: setAnimationChannel(topicId, channel),
           removeAnimationChannel(topicId),
           getAnimationChannel(topicId)

File: src/hooks/useTopicData.ts
- After subscribing the animation broadcast channel, registers it via
  setAnimationChannel(topicId, channel).
- On cleanup, calls removeAnimationChannel(topicId).

File: src/hooks/useChatMessages.ts
- Instead of creating an ephemeral channel, calls
  getAnimationChannel(topicId) to retrieve the existing persistent channel.
- Sends the broadcast directly on that channel instance.
- No channel creation/removal needed.

Result: The sender and receiver now use the SAME channel instance,
ensuring reliable delivery of `message-animation` events.

==================================================
11) KEY TAKEAWAY
==================================================
When using Supabase Realtime broadcast for same-tab communication:
- NEVER create ephemeral channels with the same name as a persistent listener.
- ALWAYS reuse the existing channel instance for sending.
- Use a shared registry pattern to pass channel references between hooks.
